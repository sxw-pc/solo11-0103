# 能耗抄表采录台

园区离线抄表结算证据流水线。读取本地批次契约、表位谱系、倍率生效区间、换表记录和手持终端 CSV。输入只用合成样本，运行时不联网。

## 运行

Python 3.11+，运行期仅标准库。`python -m pip install -e .` 安装；`python -m meterround demo` 一条命令创建临时数据库并打印 JSON 报告路径，旁边同时生成 Markdown；`python -m meterround --help` 查看独立初始化、导入、判定、查看和报告命令；`python -m pytest -q` 测试。

## 业务流与实体

批次 Batch → 表位 Slot → 按时段绑定的表计 Assignment；倍率 Multiplier 和换表 Replacement 与表位关联。来源 Source 用 SHA-256 去重，读数 Reading 用设备与序号幂等；原始行和行号不可覆盖。Issue 保留身份冲突、缺读、窗口、回卷、换表、倍率、零耗和尖峰证据；Decision 给出可结算或待核。所有写入在 SQLite 事务内完成，重复运行重算决策但不复制证据。错误由稳定 code 表示。

运行台账 Run 与业务判定在同一事务内写入；Evidence 逐条关联读数、来源哈希与载荷哈希。导入失败时整次事务回滚。

## 判定

同一表计计算读数差；接近量程末端跳到零附近才认为回卷，否则待核。换表需有旧表末读、新表初读和生效时间。倍率按读数时间区间拆段，缺口使结论待核。零耗、异常突增、缺读或超出抄表时窗也待核。报告保存分段算式和证据读数 ID。当前仅处理单表位结算，暂不引入计价、分摊或遥测。

## 园区需求响应（空调启停规划与执行）

`meterround/demand_response.py` 在不改动抄表用量、账单补差与绿色属性表的前提下，增加最多 4 楼、8 时段的本地精确规划。登记 case 时逐楼用 `device+slot` 回查既有 reading，并比对关联 `source.sha256`；读数时区不一致、来源 SHA 冲突或输入缺项直接拒绝。

- **物理模型**：每段后温 = 上段实况温度 + 本楼增温 −（启动时）制冷量；超出本楼温度上限的正温差逐段累加为热暴露，只增不减，后期制冷不能倒扣既有暴露。
- **硬约束**：每段两楼合计功率不超过电网功率上限；实际削减量达到冻结承诺 `minimum_shed_kw_each_period`；同时满足全园区暴露总额与逐楼暴露上限；不得低于最低温度。
- **精确最优**：规划器枚举每段全部合法负载子集，做带支配记忆的深度优先穷举（无近似、无贪心），按合同字典序择优。`min_energy` 先最小化用电整数分、再最小化最大逐楼暴露；`min_max_zone_exposure` 先最小化最大逐楼累计暴露、再最小化用电分。证据载荷含节点数、枚举转移数、剪枝数与可行序列数，可独立对拍复核“无更优计划”。
- **计划与实物分离**：`dr_plan`/`dr_command` 只记录待执行命令；`dispatch` 推进物理时段并写 `dr_action`/`dr_zone`，重复同一执行请求返回 `replayed`，物理时段不重复推进。已执行时段不可倒写。
- **迟到反馈**：温度反馈只校正未来时段的起点温度与剩余暴露额度；关闭时段的反馈标记 `late_feedback_immutable` 留痕但不改实况。旧暴露不可追回、设备容量变化、计划起点漂移、来源冲突或时区错位时命令置 `待核`，不发无法履约的控制令。

CLI：`dr-register` 登记、`dr-plan --contract {min_energy,min_max_zone_exposure}` 规划并可 `--out` 导出 JSON 控制证据、`dr-execute` 逐段执行、`dr-feedback` 录入温度反馈、`dr-state` 查看实况。证据 JSON 逐段记录来源摘要、设备动作、功率/承诺差额、前后温度、暴露累计、费用、最优性证明与执行/待执行状态。
