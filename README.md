# 能耗抄表采录台

园区离线抄表结算证据流水线。读取本地批次契约、表位谱系、倍率生效区间、换表记录和手持终端 CSV。输入只用合成样本，运行时不联网。

## 运行

Python 3.11+，运行期仅标准库。`python -m pip install -e .` 安装；`python -m meterround demo` 一条命令创建临时数据库并打印 JSON 报告路径，旁边同时生成 Markdown；`python -m meterround --help` 查看独立初始化、导入、判定、查看和报告命令；出账用 `python -m meterround bill --db <db> --contract <contract.json> --out <bill.json>`（`--contract` 可重复）；`python -m pytest -q` 测试。

## 业务流与实体

批次 Batch → 表位 Slot → 按时段绑定的表计 Assignment；倍率 Multiplier 和换表 Replacement 与表位关联。来源 Source 用 SHA-256 去重，读数 Reading 用设备与序号幂等；原始行和行号不可覆盖。Issue 保留身份冲突、缺读、窗口、回卷、换表、倍率、零耗和尖峰证据；Decision 给出可结算或待核。所有写入在 SQLite 事务内完成，重复运行重算决策但不复制证据。错误由稳定 code 表示。

运行台账 Run 与业务判定在同一事务内写入；Evidence 逐条关联读数、来源哈希与载荷哈希。导入失败时整次事务回滚。

## 判定

同一表计计算读数差；接近量程末端跳到零附近才认为回卷，否则待核。换表需有旧表末读、新表初读和生效时间。倍率按读数时间区间拆段，缺口使结论待核。零耗、异常突增、缺读或超出抄表时窗也待核。报告保存分段算式和证据读数 ID。

## 出账与补差

账单只读取同一批次、同一决策快照的总表与租户分表；总表与任一分表待核、总表用量小于分表之和（负公共池）、租户重复归属、价格无效或结算时段不一致时，整张账单记为 `待核`，不截零、不部分出账。

总价以整数分记账：直接用量费用按户最大余数法取整，公共池 = 总表费用 − 分表直接费用，再按合同约定的 `usage_share`（本期直接用量比例）或 `capacity_share`（签约容量比例）用最大余数法分完最后一分，各户金额之和恒等于总表金额。两种划分是各自独立的有效责任划分，各自维护台账。

已开票 `INV-001` 与其发行行只读保留。每次出账是独立 `revision`：净补差 = 本账单户金额 − 同一合同同一批次已开票金额。同一合同、同一决策快照重复出账不新增分录；补录读数或规则升级使快照哈希变化时，新 revision 先冲回上一条有效调整，再按新快照形成净补差，绝不与既有账单或 `INV-001` 累计重复收费。每条金额分录引用合同、批次、参与 decision、来源哈希与证据哈希，`store.statement` 可沿发行、冲回追到当前净应付/应退。
